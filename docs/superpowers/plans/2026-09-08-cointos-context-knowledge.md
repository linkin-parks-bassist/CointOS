# D11: Context preparation and the knowledge roles

Owner: coordinator; recorded by Aster (Astra), 2026-09-08.
Phase: post-MVP intended work, not a POC prerequisite. Governing contract:
[decision 0020](../../decisions/0020-context-briefings-lecturers-and-advisers.md).
These are planning boundaries, not ready-to-run implementation prompts. Before
each dispatch bind exact files, necessary evidence, authority, resource/time budget
and stopping condition to the actual accepted interfaces. Use local workers for
small implementation/review slices; preserve independent acceptance.

- [ ] D11.1: Define the minimal orientation and briefing artifact contract at A1's
  context compilation boundary and D9's runner adapter. Include revision/dirty-input
  provenance, observation time, source authority, scope and freshness semantics.
  Acceptance: a reader can distinguish stable guidance, observed runtime facts and
  unverified assumptions without rediscovering the repository.
- [ ] D11.2: Assemble a task-specific brief just before dispatch from maintained
  repo orientation and selected evidence. Preserve that exact artifact and deliver
  contents in the initial prompt where supported, with an explicit no-repeat-
  discovery instruction. Acceptance: a source change is detected or marked stale;
  unchanged scoped facts do not trigger a duplicate orientation sweep; prompt size
  fits admission. Measure first useful action and prefill as well as tool reads.
- [ ] D11.3: Add Lecturer as an ordinary role definition plus bounded topic tasks.
  Produce one sourced narrative Markdown lecture and a searchable topic entry.
  Acceptance: another worker can find the relevant explanation, its prerequisites,
  applicability and status without reading the entire archive. Scope and authority
  inherit the requesting task; authorship does not imply independent review.
- [ ] D11.4: Add specialized Auditor lecture tasks and version-bound review records.
  Acceptance: injected factual/omission defects are caught, source changes mark
  affected material stale, and a reviewed old version cannot endorse a replacement.
- [ ] D11.5: Add Adviser as an ordinary role and topic-learning task. Consume all
  applicable lectures in bounded rounds and record coverage/version references.
  Acceptance: it cites relevant knowledge, states gaps and refreshes affected
  knowledge after a lecture changes. No unsupported claim of complete expertise.
- [ ] D11.6: Compose durable Adviser identity, mailbox and resource reacquisition
  using B1/B4 and R5/R6, with D10 snapshot support where qualified. Acceptance: idle
  addressability costs no physical inference slot; a question survives suspension,
  is answered after resumption, and preserves budgets and access boundaries.
- [ ] D11.7: Review one end-to-end knowledge exchange and measured orientation
  savings. Report extra prompt/restore costs and stale-knowledge failures honestly.

Do not add an autonomous role schedule, daemon, new database, broad document crawl
or global role rename as an incidental step. Such operational choices need their
own concrete task boundaries. Keep future proposals in the existing discovery and
handoff path. D11 does not authorize remote inference or cross-project disclosure.
