# Complete CointOS MVP bring-up

Status: accepted by David for implementation and activation, 2026-09-05. Organized by
Astra (Codex `/root`). Merge and publication remain separately controlled.

David requested a complete minimal running OS rather than exhaustive hardening of
the old survival slice before it is useful. The binding principles are Coin stays
available, no OOM, and seamless handovers across dynamic contexts. The architecture
must support autonomous/spontaneous role work, real agent-agent communication,
configurable mechanically enforced priorities, and ongoing verified improvement.
David selected Cointelprofessional for approval before activating such changes.

The [new design](../specs/2026-09-05-cointos-mvp-design.md) and
[execution index](../plans/2026-09-05-cointos-mvp-index.md) replace the
old delivery sequence for review. Retain protocol laws, evidence and sound narrow
mechanisms; replace incompatible controllers, resident-resource bypasses and
diffuse role generation without permanent compatibility paths. Early contact is
C5; complete autonomous acceptance is A5 after health, messaging and release proof.

Expected policy is validated configuration interpreted by its owner, using
existing standard parsers. Priority is Sole Survivor > Coin > small inspector >
large inspector > other roles; rank does not consume Coin's reserved physical slot.
New roles are Markdown plus configuration, not scheduler switches. All model
requests go through shared measured admission. Communication uses durable mailboxes
at asynchronous runner boundaries, not a generic actor framework between functions.

Under a hosted coordinator, workers are GPT-5.6 Sol medium plus short bounded
local jobs; a local agent dispatches local workers only and never spawns
hosted-model workers (David's direction, 2026-09-05). Before smoke, Codex
closes admission and waits for local completion/checkpoint AND process/request
exit. Candidate code cannot be live imported before verified, digest-bound approval
and fixed recoverable activation. Protected self-update requires separate contact
continuity proof; the release manager's own upgrade remains operator-led.

Consequences: the proposal keeps more essential infrastructure than a Telegram-only
demo, but defers broad hostile/crash/soak/model matrices to one bounded queue. The
design is not a claim of current runtime correctness or a universal availability
guarantee. No execution, service or publication authority follows from this note.
