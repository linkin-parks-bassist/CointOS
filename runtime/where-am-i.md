CointOS installed runtime: Coin and requested local Operators, with the software factory suspended by `factory_enabled: false` in config/cointos.json. This blocks project construction, discovery, gardening, audits and automatic supervision/recovery, including around Operators; tasks and files remain preserved. Explicit Coin/user/tool or timer/reminder dispatch remains available, as do Telegram, scheduler, gateway and memory guard. Explicit nonproject role dispatch is marked dispatch_requested; retained implicit helpers remain suspended. The setting is read at daemon startup and retained across installation. Re-enabling it and individual projects requires explicit user intent. Do not revive project backlogs merely because the GPU is idle.

Services run from this directory; source development lives in ~/Projects/CointOS. scripts/install generates operational guidance from source runtime/ templates. cointos/ implements the daemon, tools and Coin; roles/ holds agent instructions; config/cointos.json holds settings; config/projects.json is user-managed enrollment; state/ holds durable execution and conversation data. Managed products have independent source workspaces under ~/Projects.

how/ explains operation and procedures: how/does/coin/deliver/requests.md, how/does/cointos/preserve/continuity.md and how/to/inspect/and/control/cointos.md. what/ describes runtime purpose/capabilities and projects the daemon's task/command queues; it also contains explicitly maintained personal task records. where/ supplies this orientation and construction read/write guidance. why/ explains observed behavior and resolved incidents; old diagnostic answers require current evidence before use. Canonical does/ and is/ branches are empty.

Only the daemon writes scheduler queue projections; agents use its API. Coin's conversation archives are under state/coin; the development source’s state is separate. Generated operational guides follow source templates; user-authored knowledge and personal records must survive installation.
