CointOS runs local OpenCode agents through a pre-emptive GPU gateway on the user's workstation; Coin is its Telegram control. `cointos status`, `agents`, `jobs`, `task PROJECT:TASK` and `check` inspect the daemon. `jobs` includes every unfinished task plus recent terminal history. Managed agents omit completed standalone runs unless `--all` is requested; recent queue outcomes and failures remain visible; `jobs --project PROJECT` filters before selecting history, and `--all` is for historical investigation. `task` shows the current linked queue assignment, binding accepted tests, typed pending corrections, receipts and holds. Recovery launches use the same view. An old completion report retained after restart/revision is marked in historical_fields and available only through --history when there is no current receipt. `task PROJECT:TASK --history` retrieves full historical execution narratives without changing authority. The work frontier shows the current recovery owner and runnable corrective children; blocked work without either fails the progress diagnostic. `stop` pauses autonomous agents and `go` resumes them. `cointos kill AGENT` terminates the run and durably holds unfinished work uncharged with its artifacts preserved. `cointos resume PROJECT:TASK` explicitly releases that hold; `go` does not. Process control never decides task failure. The source repository's knowledge tree (~/Projects/CointOS/.knowledge) is the maintained description; this answer summarises what an agent working here needs.

For a disposable local OpenCode session through the scheduler, run cointos-private. Its in-memory database and isolated temporary stores do not join the normal session history. The private gateway skips prompt capture and persistent context caches. The launcher inherits ordinary user configuration, including native tools, MCPs, hooks/plugins, skills and permissions; its overrides control private storage and local inference. Ancestor/station AGENTS.md paths are explicit, and hook state is temporary. Plugin changes require a fresh private launch; preserve existing in-memory conversations. It forwards terminal resize signals. The dashboard shows active user requests with token counts only; Active clients derives managed, Coin and user ownership from the same ledger. Normal OpenCode cointos/default sessions still retain their usual history. Terminal scrollback and deliberate tool-written files are separate.
