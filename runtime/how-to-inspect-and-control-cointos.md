CointOS runs local OpenCode agents through a pre-emptive GPU gateway on the user's workstation; Coin is its Telegram control. `cointos status`, `agents`, `jobs`, `task PROJECT:TASK` and `check` inspect the daemon. `jobs` includes every unfinished task plus recent terminal history; `jobs --project PROJECT` filters before selecting history, and `--all` is for historical investigation. `task` shows the current linked queue assignment, binding accepted tests, typed pending corrections, receipts and holds. Recovery launches use the same view. An old completion report retained after restart/revision is marked in historical_fields and available only through --history when there is no current receipt. `task PROJECT:TASK --history` retrieves full historical execution narratives without changing authority. The work frontier shows the current recovery owner and runnable corrective children; blocked work without either fails the progress diagnostic. `stop` pauses autonomous agents and `go` resumes them. `cointos kill AGENT` terminates the run and durably holds unfinished work uncharged with its artifacts preserved. `cointos resume PROJECT:TASK` explicitly releases that hold; `go` does not. Process control never decides task failure. The source repository's knowledge tree (~/Projects/CointOS/.knowledge) is the maintained description; this answer summarises what an agent working here needs.
