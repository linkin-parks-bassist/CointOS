**Budgets and reasoning.** Default effort is low, with medium for test writers, managers and integrators; each integrator uses its own setting, not the worker's override. Each run has a pinned generation budget from `recovery.generation_seconds`/`generation_tokens`, with optional role defaults in `recovery.role_budgets` and explicit task overrides taking precedence. The common allowance applies equally to managers and Operators; there are no shorter configured role overrides. Waits, prefill and tools are free. Launch messages state the effective budget and reasoning cap. At `recovery.warning_fraction` of either limit the run gets one warning to finish or report blocked within its remaining allowance. Exhaustion preserves branch/files and evidence. `recovery.role_fresh_retries` overrides `recovery.fresh_retries`: workers, managers, integrators and Operators have no fresh budget retry by default. Failed workers reach one recovery controller instead of another automatic full allowance; other roles retain their configured retry policy. This does not disable session recovery after transport/process interruption. Each canonical assignment/version gets one independent repair Operator, deferred while a valid child frontier can progress. Managers can dispatch and finish atomically with cointos_handoff; recovery Operators can hand off to existing work and finish atomically with cointos_replace or request independent correction and finish with cointos_correct_tests. The failed manager remains unaccepted. Launch notices and warnings do not promise automatic recovery after exhaustion. The Operator must establish a checked handback and cannot recursively spawn automatic repairs; without an eligible recovery or corrective handoff, unfinished work remains blocked. `cointos budget PROJECT:TASK` changes waiting work or explicitly increases a running task outside validation. Live decreases are refused. Increases preserve generation already spent, grants, session, run count and artifacts; the agent receives the new limits and can be warned against the raised allowance. Configuration changes alone do not rewrite pinned tasks; `cointos reasoning PROJECT:TASK LEVEL` changes effort from the next reply.
