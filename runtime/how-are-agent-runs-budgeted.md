Personal mode (`factory_enabled: false`) disables automatic supervisors, mandatory splitters and First Responders, including around Operators. Idle capacity, token/GPU milestones and failures create no additional agents. Explicit Coin/user/tool or timer/reminder dispatch remains available. The factory-enabled mechanisms below are retained for explicit re-enablement.

**Budgets and supervision.** Elapsed time never automatically ends a run. Legacy generation_seconds allowances are compatibility metadata, not active limits. Token budgets remain pinned from defaults, role settings and explicit overrides: ordinarily 2,000,000 tokens; First Responders 30,000; Supervisors uncapped. A token-only warning precedes token exhaustion. Waiting, prefill and tools do not consume generated-token allowance. Unchanged work does not receive automatic fresh token funding; authorised interruptions preserve sessions and work. Unreceipted death still reaches First Responder recovery.

Tasks should finish or hand off within 30 GPU minutes. Supervisors judge useful advancement from evidence; activity, rereading and token accumulation do not establish progress. Current-run GPU time and token counts are available in task inspection and their launch. GPU service includes prefill, generation and switching, excluding waits/tools. A check is requested at each 5,000-output-token boundary or configured 30-GPU-minute milestone, coalescing while pending. There is no recursive supervision. Only implementation workers stop at the existing 40k output threshold for a mandatory two-child split; managers/integrators do not.

Use token-budget controls for waiting work or explicit live increases; usage, grants, sessions and artifacts remain. Old numeric time arguments do not reintroduce an enforced stop. Reasoning effort/caps are separate from run budgets: the installed original-steer retry has no per-block reasoning caps. Detailed requirements and evidence belong to the source budget and supervision owners.
