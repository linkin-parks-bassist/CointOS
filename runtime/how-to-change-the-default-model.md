The dashboard Machine panel discovers downloaded GGUFs and configured downloaded Lemonade models, and offers Default model. POST /api/default-model accepts the exact path identifier from GET /api/models. Lemonade choices use lemonade:MODEL and let the service resolve protected checkpoints and split files. Current replies finish, the previous default unloads, and the selected model loads after memory/native checks. Sessions and work survive. Errors remain visible; failed loads attempt restoration. Ordinary agents and Coin follow work_model; optional coin.model is an explicit separate requirement. Only required engines load. Source recipes can specify qualified speculative drafts; new disk discoveries use Gufo without an unqualified draft.

The shared default must support resident inference state for private sessions. An incompatible selection is rejected before unloading the current model.

Coin, agents and ordinary/private sessions share the configured model context uniformly. The current Flash-Next recipe uses one 128k server slot and one CointOS lane; CointOS schedules clients.

Use opencode --model cointos/default for user-driven GPU sessions after configuring the cointos provider at http://127.0.0.1:4200/v1. It shares the loaded model; user work has a high scheduling weight and Coin a larger weight. Coin takes precedence at completed backend steps; other requests share time slices by local priority-weighted random choice, without usage accounts. Starting an independent engine bypasses this scheduling.
