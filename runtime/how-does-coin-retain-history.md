**Coin history.** `coin.history_messages` is the upper threshold (20) and `coin.history_trim_messages` is the discard batch (7). When conversation history reaches twenty messages, discard the oldest seven from the prompt, leaving thirteen, then append until twenty and repeat. Incoming text/captions and every accepted outgoing Telegram message count, including attention notices and explanations; captionless attachments use independent filesystem intake and do not enter chat history; internal clocks, saved-wake instructions and tool transcripts do not. Before enough history exists there may be fewer than thirteen. New active requests are never discarded. Legacy photo-only user receipts are excluded before selecting the window; captions remain conversational. The append-only on-disk conversation archive and timestamps remain intact. One conversational egress archives each accepted outgoing part, including partial sends, under a file lock with chat-scoped Telegram message IDs. Mid-turn deliveries enter the next model prompt. Durable reply-to references retain the quoted message even after history rolls. Telegram update IDs make history recording idempotent on retry; current pending IDs are excluded from the historical prefix. In model context, archived media receipts use cointos-archived-attachments and pending input uses cointos-current-input with its update ID. Archive bytes retain the original content; old receipts are historical observations, not current filesystem proof.

Coin marks the selected history as a reusable native prefix. A per-user semantic prefix checkpoint survives changing round clocks, timelines and tool tails independently of the near-tail checkpoint. Growing history can restore it; batch rollover invalidates changed user prefixes but retains shared system/tool starts. Cache eviction, changed instructions/tools and rollover can still require prefill. There is no fixed twenty-four-second startup timer. The Telegram polling timeout is a maximum wait for updates, not a delay before responding to an arriving message. Cache and latency improvements require measured evidence; preserve the distinction between saved history, cache state, model generation and Telegram delivery.
