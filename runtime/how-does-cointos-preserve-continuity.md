**Continuity and restart.** A managed task pins the complete system/developer prefix from its first model request, and the gateway journals a digest of each request's system prompt without retaining the prompt. The state lock protects diagnostic byte staging; file flushing is ordered outside that lock, before ledger publication and at shutdown. An abrupt kill can lose queued diagnostics; the journal never owns task authority. Under three hours, relaunch reuses an unfinished turn's original user message through a one-shot OpenCode hook, preserving its ID, timestamp and parts. A completed reply gets `Continue.`; a longer gap gets one concise reorientation. First, the supervisor completes pending compaction through native summarize with automatic continuation disabled; a failed summary withholds recovery. `cointos restart` stops new agent spawning but lets existing conversations issue continuation thoughts and receipts until a quiet request boundary, then replaces only the daemon. Full shutdown attempts model-context saving, disk snapshot persistence, final ledger saving and a final journal flush independently, so one failed step does not suppress the others.

Before a fresh task pins its tools, Bash cites its scratch location through `$COINTOS_SCRATCH/opencode` instead of a literal run ID. The environment still identifies the separate current run directory; expand it before passing absolute paths to tools. Schemas and permissions are unchanged, and existing pinned definitions/history remain intact. Common definitions precede role-specific CointOS tools. A fresh launch also marks the exact common-tool prefix for caching under existing snapshot admission/eviction, so different roles can reuse it after it warms.

New managed OpenCode launches attach observed task authority, accepted bindings, local checkout HEAD/manifest count and remaining generation budget to native compaction summaries through the text-completion hook. Reads are bounded and do not read hidden packet contents. Missing or revoked authority is explicitly unavailable; a metadata lookup failure omits the anchor without changing ordinary replies. Model prose remains unverified. Re-read cointos_task and inspect actual files/targets before acting: accepted packet contents are not materialized checkout facts. The snapshot can become stale. Existing servers retain their loaded plugin and environment.

A model stop with no nonblank answer and no tool calls is an incomplete response, even if reasoning tokens were generated. After any existing construction pre-stop check, the gateway sends incomplete_response as HTTP 502 or an explicit streaming server error rather than a successful stop. Native OpenCode retries that error within the same process; actual model recovery still requires observation. Token-limit replies preserve length continuation. This does not grant more budget, synthesize a receipt or reopen exhausted work.

For configuration-compatible changes, `scripts/install --live` copies prompts, dashboard and CLI in place if daemon code/configuration is unchanged and dependency aliases need no migration. Validation and completion requests hold a shared replacement lease through receipt recording and queue publication; daemon installation needs exclusive ownership before stopping or copying. Busy installation and request admission refuse without waiting. Prompt/dashboard/CLI-only refreshes remain possible during validation. A legacy daemon without the lease requires a separately established quiet boundary for its first upgrade. Otherwise it replaces cointosd around surviving agent units: shutdown saves lane state and cuts replies. Stored same-project dependency aliases are migrated while stopped, preserving assignment versions, holds, sessions and receipts; conflicting or foreign metadata refuses before changes. OpenCode retains partial output. Nonempty consecutive assistants use explicit continuation; empty final assistants use a new generation opening, with the native explicit-continuation patch preserving all history. Managed recovery remains under observation. It refuses changes to gateway/backend/model process identity or topology, which require a paused full installation. Failure after cointosd stops restarts it on exit. Coin keeps imported code and startup settings, so changes to those need a separate quiet Coin refresh. Existing MCP servers also retain their imported CLI; fresh servers receive updated client modules. The source procedure `how/to/install/cointos.md` owns deployment details.
