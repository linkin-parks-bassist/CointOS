**Continuity and restart.** A managed task pins its project/harness system prefix and tool definitions separately for each harness protocol; the current running MCP server’s owned workflow instructions and OpenCode 2 tool catalog refresh without erasing history, and the gateway journals a digest of each request's system prompt without retaining the prompt. The state lock protects diagnostic byte staging; file flushing is ordered outside that lock, before ledger publication and at shutdown. An abrupt kill can lose queued diagnostics; the journal never owns task authority. Under three hours, OpenCode 2 relaunch retains an unfinished turn's original user ID, timestamp, text and completed tool results, then admits a native synthetic recovery control. Surviving V1 runs retain their original one-shot hook. A completed reply gets `Continue.`; a longer gap gets one concise reorientation. First, the supervisor completes pending compaction through the matching native API and waits for a completed summary; a failed summary withholds recovery input. Automatic compaction remains disabled. `cointos restart` stops new agent spawning but lets existing conversations issue continuation thoughts and receipts until a quiet request boundary, then replaces only the daemon. Full shutdown attempts model-context saving, disk snapshot persistence, final ledger saving and a final journal flush independently, so one failed step does not suppress the others.

Before a fresh task pins its tools, the shell description cites its scratch location through `$COINTOS_SCRATCH/opencode` instead of a literal run ID. The environment still identifies the separate current run directory; expand it before passing absolute paths to tools. Schemas and permissions are unchanged, and ordinary pinned definitions/history remain intact; current CointOS declarations follow the running MCP server. OpenCode 2 calls MCP through execute and the exact tools.cointos and tools.knowledgetrees catalog signatures; ordinary filesystem tools remain direct calls. V1 retains direct MCP declarations. A fresh launch also marks the exact common-tool prefix for caching under existing snapshot admission/eviction, so different roles can reuse it after it warms.

New managed OpenCode launches attach observed task authority, accepted bindings, prepared-source identity/file count and remaining generation budget to native compaction summaries through the V2 compaction HTTP-response hook (the V1 text-completion hook remains attached to surviving V1 runs). Reads are bounded and do not read hidden packet contents. Missing or revoked authority is explicitly unavailable; unavailable context gets an explicit fallback, and ordinary replies are unchanged. Model prose remains unverified. Re-read cointos_task and inspect actual files/targets before acting: accepted packet contents are not facts about the prepared files. The snapshot can become stale. Existing servers retain their loaded plugin and environment.

A model stop with no nonblank answer and no tool calls is an incomplete response, even if reasoning tokens were generated. After any existing construction pre-stop check, the gateway sends incomplete_response as HTTP 502 or an explicit streaming server error rather than a successful stop. Native OpenCode retries that error within the same process; actual model recovery still requires observation. Token-limit replies preserve length continuation. This does not grant more budget, synthesize a receipt or reopen exhausted work.

For configuration-compatible changes, `scripts/install --live` copies prompts, dashboard and CLI in place if daemon code/configuration is unchanged and dependency aliases need no migration. Validation and completion requests hold a shared replacement lease through receipt recording and queue publication; daemon installation needs exclusive ownership before stopping or copying. Busy installation and request admission refuse without waiting. Prompt/dashboard/CLI-only refreshes remain possible during validation. A legacy daemon without the lease requires a separately established quiet boundary for its first upgrade. Otherwise it replaces cointosd around surviving agent units: shutdown saves lane state and cuts replies. Stored same-project dependency aliases are migrated while stopped, preserving assignment versions, holds, sessions and receipts; conflicting or foreign metadata refuses before changes. OpenCode retains partial output. Nonempty consecutive assistants use explicit continuation; empty final assistants use a new generation opening, with the backend's native continuation handling preserving all history. Managed recovery remains under observation. It refuses changes to gateway/backend/model process identity or topology, which require a paused full installation. Failure after cointosd stops restarts it on exit. Coin keeps imported code and startup settings, so changes to those need a separate quiet Coin refresh. Existing MCP servers also retain their imported CLI; fresh servers receive updated client modules. The source procedure `how/to/install/cointos.md` owns deployment details.
