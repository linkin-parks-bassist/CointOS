**Agent tools and messages.** Agents use role-limited MCP controls. In OpenCode 2, call the exact catalog signature through `execute`, for example `return await tools.cointos.task({})`; its JavaScript arguments are ordinary objects. Surviving V1 runs use direct `cointos_<command>` tool names. Brief text remains a string argument. `cointos_peers` shows other live runs, their purpose, activity and changed files; `cointos_send` messages an active task (`PROJECT:NAME`), `user` (a durable question/message for Telegram delivery; acceptance is not proof of reading), or `mailbox:NAME` (a local external inbox without alerts). External clients read with `cointos inbox --mailbox NAME` and send as themselves with `cointos message --mailbox NAME TO TEXT`; agents cannot use external mailbox identities. `cointos_inbox` reads the agent's unread messages, which tool results announce. Messages coordinate; work moves only through the queue.

For a refused operation, use the assigned scope and normal recovery; the original diagnostic remains in the run record. Use declared tool fields only. Unsupported arguments refuse rather than silently changing the scope of a check. The V2 adapter preserves extra fields until broker validation; a successful execute wrapper does not mean an enclosed operation was accepted. Read each result before continuing. resume only releases an infrastructure admission_hold; it does not retry failed work. Use task/log to inspect failures and their recovery owner. A task that never prepared files may have no source view; use project for accepted source and log for execution records. cointos_check_work checks the caller or a declared proposal and reports binding tests; it has no arbitrary task-target field. Supervisors may omit task on cointos_task and cointos_log to inspect their declared subject; explicit targets remain exact. cointos_task shows the canonical queue brief and full checked receipt once, with binding tests and typed correction owners. history=true retrieves complete execution metadata, including the original execution briefs and duplicate report fields. cointos_jobs lists current work and recent queue outcomes; completed standalone runs require all=true. Active runs and recent failed runs remain visible. Filter by project for current work discovery.

preserved_inputs names retained source tasks and their roles. Compatible files are prepared automatically in the new assignment; managers can dispatch the appropriate role for other preserved inputs without copying files or expanding their own scope.

Delivered messages can yield an active reasoning request at its next complete generation step so the same session rereads current guidance. Writing and tool execution continue without interruption. Delivery is not proof that the recipient has acted on the message.

Coordinators use cointos_log for an assignment's numbered record; filter the index, then read selected entries with show. cointos_source reads accepted project source or a task's current files: name exactly one project or task, omit path to list files, or give a relative file to read numbered lines. Task listings show changed files. Use start and limit to page. Maintained answers remain under knowledge-tree tools. Task inspection names only your own assigned directory; inspect other assignments through source or diagnostic controls. These observations come through CointOS; do not search peer storage or copy old workspaces. Supervisors and First Responders may inspect Coin's record; other coordinating roles inspect assignment records.

Test auditors use cointos_diagnostic with project to prepare accepted files in scratch for builds, suites and counterexample mutations. Integrators use diagnostic to list/copy retained worker probes. cointos_metrics summarizes pipeline landings, gate returns and recovery spending over a recent hours window, with retained journal coverage; managed clients do not open runtime journals.
