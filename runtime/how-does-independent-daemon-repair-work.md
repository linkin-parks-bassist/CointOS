**Independent daemon repair.** Fatal Python daemon failures trigger `cointos-repair.service`, using the installed authenticated Codex CLI's remote provider with explicit non-Git runtime support outside the local gateway. It retains its conversation in `state/repairs/`. The daemon verifies original saved authority before adoption and publishes startup evidence tied to its PID and surviving native identities. The repair checker matches that evidence to the incident and checks current health/enrollment; authorised revision, retry and cleanup after startup remain valid. It never edits the ledger or keys. Installation shares its ownership lease; repair waits through copying, and installation refuses while repair owns the runtime. Native retries use `service_restart_seconds` without an inherited start cap. The remote harness bypasses managed run budgets; professional-data disclosure follows the assignment. Managed Operators require the local model.

An explicit runtime installation supersedes an unfinished older repair assignment while holding the shared ownership lease. It stops the waiting repair service and preserves its original snapshot and events. The terminal record is blocked/superseded, never a false repair certification; a later startup failure captures a fresh baseline.
