**Checked handoffs.** Queue/revise tools carry summary, dependencies and test-contract relies_on as structured fields. Briefs describe product behavior; changed-file declarations and special acceptance lines are not required. cointos_check_work validates a draft without queueing it, or checks the caller's existing frontier. It reports malformed IDs, unknown prerequisites, cycles and missing declared APIs. cointos_handoff atomically creates manager children and completes planning; malformed or dead batches leave no partial queue. Recovery cointos_replace checks the existing replacement graph and landed controller artifacts before repointing dependencies and completing atomically; exact retries replay its receipt. Recovery correct-tests similarly queues the independent correction and completes checked handback atomically; failures leave no partial child. Manager completion refuses dead queued handoffs with exact errors, allowing correction in the same run. Ordinary dependency waits remain valid. Agent revisions of implementation/integration work cannot discard accepted test-contract dependencies: the tool refuses before mutation and names the packets to retain. Build repair does not withdraw acceptance tests; changed contracts use cointos_correct_tests for independent correction. An explicit user revision can withdraw a dependency. Identical revisions do not restart tasks or refill budgets. An origin revision by another owner cancels stale recovery controllers without withdrawing the corrected item or losing files. A recovery controller can finish its own correction.

`Depends on:` contains comma-separated item IDs only, with optional same-project qualification. Explanations belong on another line; malformed IDs are refused before mutation. Unknown but well-formed forward references still wait for their prerequisites and can trigger bounded repair.
