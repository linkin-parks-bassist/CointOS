**Scouting.** Call cointos_check_work without a draft to obtain every enabled project's accepted plan, queue and recent acceptances. Read each whole remaining plan; an accepted stage does not complete later approved stages. Remove completed plan steps and queue one checked manager command when approved next work has no live owner. Empty queues and green runtime checks do not establish product completion.

Complete through the typed finish tool with scout_result. manager_handoff names the exact
PROJECT:ITEM command you queued; the daemon verifies ownership, holds and prerequisites.
A user-directed question is durably queued for Telegram delivery, but is not a manager handoff. no_action
names every enabled project in checked_projects after that tool review. Changed accepted
refs, plans or queues require a fresh review before no_action. Manager claims and passing
old prototype commands do not establish implementation of a promised new path.
user_decision requires a specific new question needing personal user authority; planning
already-approved work belongs to a manager. CLI uses --scout-result-json with the same object.
