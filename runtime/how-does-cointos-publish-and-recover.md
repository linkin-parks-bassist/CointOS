**Publication and recovery.** Reviewed landings and maintenance merges use nonblocking repository ownership and atomically update accepted main by its expected ref. A dirty main checkout keeps files and staging on a draft branch; clean checkouts refresh and switched workspaces remain independent. Ref-only draft handoff preserves even unresolved index stages, conflict markers and merge metadata while accepted main advances. Contention refuses immediately; mechanical Git bypasses hooks without changing editor configuration. Owned HEAD locks recover after process death by matching inode; external locks remain. Before publication the daemon persists a verified intent pinned to the candidate, worker receipt and assignment version. Published matching intents settle before surviving units are adopted or their budgets enforced, even without old worktrees or another model review. Holds and stale runs revoke validation results before acceptance or failed-test bundling. Test commands serialize shared host temporary outputs through a process-owned lock which survives their daemon; external builds remain outside it. Harnesses must build and execute artifacts in fresh invocation-owned directories with cleanup; fixed host temporary executables can produce false passes under external overwrite. Protected harness repairs follow ordinary test-contract review.

Maintenance publication checks every unpublished commit, including reverted edits. Managers and tree maintenance publish Markdown knowledge only. Project Operators may also publish configured non-code maintenance; production and protected tests/harnesses require worker submission and independent review. Protected paths override non-code patterns. An explicitly assigned system Operator retains its infrastructure scope. check_work reports those committed-history violations plus forbidden staged, unstaged and untracked maintenance paths before publication; refusal preserves branches, files and main.

Maintenance rechecks each changed knowledge answer against canonical files and staging before publication. Pending body, expiry or proof-policy edits, deletions and new untracked owners refuse publication and preflight without changing files/index/refs. Only status, checked_at and revised_at lifecycle metadata are ignored. Routine gardening defers these answers; health repair selects only available committed leaves. Deferred non-green leaves remain visible and are alerted once per changed deferred set. No eligible batch means no task; cached health refreshes at the existing check interval. Preserve a refused correction commit and report a blocked receipt rather than overwriting the owner.

Draft detection compares canonical files and index with their own checkout HEAD, allowing clean alternative editor branches while accepted main advances independently. Gardener completion rechecks selected answers even with no branch changes: pending owners remain unresolved and require blocked completion, not a verified-current claim. Recovery handback also retains these deferred owners.
