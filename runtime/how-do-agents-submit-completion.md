**Every run ends with one completion receipt**, checked against its artifacts: `cointos finish --complete "EVIDENCE"` or `cointos finish --blocked "BLOCKER"`. Workers edit files and submit their result; CointOS captures an immutable artifact automatically, validates it and queues review. The receipt is their whole account of it. Manager handoff captures and publishes the plan with its children; manager finish captures and publishes a completed planning concern without a separate publish step. Gardeners, tree auditors and project operators publish scoped files with `cointos merge` before completing; capture and composition are automatic. An integrator reviews with `cointos review`, then its receipt is a verified `cointos land "SUMMARY"`, `cointos incorporate PROJECT:ITEM`, or `cointos return "NOTES"`. Managers can complete planning with atomic cointos_handoff; First Responders complete existing-work handoffs with cointos_replace or independent correction handoffs with cointos_correct_tests. Correct-tests remains nonterminal for managers and ad-hoc Operators. Both record the handoff and checked receipt together. CLI commands flush their output and MCP flushes the actual protocol reply before acknowledging receipt delivery; then the daemon stops that exact managed run. Final messages, finish markers and process exit never complete a task; every unexpected run ending without a receipt fails immediately into First Responder recovery regardless of role, preserving its session and artifacts. Pre-model failures and missing runs after restart also require diagnosis. Explicit cancellation remains terminal and does not trigger recovery. A failed systemd status query keeps the observer following the run; only a confirmed terminal unit permits exit reconciliation. Run server/exit metadata publishes atomically; the observer tolerates malformed event fields and keeps valid recovery evidence. Failed metadata writes still run server cleanup. OpenCode error events remain recovery diagnostics.
Prefer the native CointOS terminal tool. Bash's default timeout can expire while the CLI's validation continues. After a dropped or timed-out request, inspect `cointos_task` for the current run's receipt before troubleshooting or resubmitting; a transport timeout alone does not establish failure or cancel validation.


An explicitly retained must_split Supervisor completes only through cointos_handoff with exactly two fresh worker jobs. CointOS carries the stopped job's original prerequisites into both children automatically; declare only additional prerequisites or ordering. Each child receives preserved files in its own workspace; use relative product paths in the brief, without directing it to the stopped workspace. The handoff replaces the stopped job and records its receipt atomically. Ordinary finish and other mutation tools are refused for this Supervisor.
