**Every run ends with one completion receipt**, checked against its artifacts: `cointos finish --complete "EVIDENCE"` or `cointos finish --blocked "BLOCKER"`. Workers commit their work on their branch, then submit that exact commit for review; the receipt is their whole account of it. Managers, gardeners, tree auditors and project operators land with `cointos merge` before completing. An integrator reviews with `cointos review`, then its receipt is a verified `cointos land "SUMMARY"`, `cointos incorporate PROJECT:ITEM --commit MAIN --worker-commit WORKER`, or `cointos return "NOTES"`. Managers can complete planning with atomic cointos_handoff; recovery Operators complete existing-work handoffs with cointos_replace or independent correction handoffs with cointos_correct_tests. Correct-tests remains nonterminal for managers and ad-hoc Operators. Both record the handoff and checked receipt together. CLI commands flush their output and MCP flushes the actual protocol reply before acknowledging receipt delivery; then the daemon stops that exact managed run. Final messages, finish markers and process exit never complete a task; a run ending without a receipt is retried a bounded number of times. A failed systemd status query keeps the observer following the run; only a confirmed terminal unit permits exit reconciliation. Run server/exit metadata publishes atomically; the observer tolerates malformed event fields and keeps valid recovery evidence. Failed metadata writes still run server cleanup. OpenCode error events remain retry diagnostics.
Prefer the native CointOS terminal tool. Bash's default timeout can expire while the CLI's validation continues. After a dropped or timed-out request, inspect `cointos_task` for the current run's receipt before troubleshooting or resubmitting; a transport timeout alone does not establish failure or cancel validation.
