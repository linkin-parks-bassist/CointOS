**Caches and memory.** The daemon removes unreachable snapshots, snapshots no conversation has saved or restored for memory.snapshot_idle_hours (36), and abandoned files, retaining conversation history and work; an expired cache only means the next turn rereads. Longer shared starts preserve shorter reusable tiers. Coin has opaque per-user cache owners; pruning one history preserves other users and the shared system start. Admission protects each active agent's unspent process growth claim and not-yet-initialized native state; snapshots cannot spend that capacity. Checkpoint admission prefers a supported idle llama slot's native serialized byte count at the held-token position; other servers use sample/native-state estimates. The RAM file and any temporary native capture claim remain reserved. Pending saves and copy-backs remain reserved across memory measurements. Snapshots give way first under memory shortage. Sustained PSI stops background agents uncharged; model unloading requires headroom still negative after shedding. Recovery waits for calm.

The retained Gufo adapter's ordinary agent switches atomically select resident per-agent inference state at completed step boundaries. Tensors, sampler/RNG and continuation state stay in place; checkpoint save/restore is separate from hot switching. First admission or changed token histories can initialize from compatible persistence hints. New resident allocation respects host headroom. A thought lacking its state allowance waits for memory off-lane; ready peers continue, and measured headroom restores eligibility. Cache reclamation runs independently. Native state belongs to a running client: cleanup releases task states with neither a run nor an in-flight thought, including review and waiting tasks. Every active thought protects its owner even without a task or recognized prefix. Historical Coin and all configured Cointel identities retain conversation residency between requests. Histories and checkpoint hints retain their longer conversation lifetime. Tool calls do not end a managed run's residency; private owners retain KV state while their client process lives, including tool/turn gaps. A tmpfs client.json receipt binds owner to PID/start ticks/boot ID; exit, zombie or PID reuse permits retirement. No transcript or key is stored in the receipt. Private owner-bound KV checkpoints use tmpfs only for ordinary prefix fallback. They cannot seed other owners, spill to disk or persist at shutdown; pressure may discard them. Capturing still requires clone-plus-file headroom. Retirement marks owners under the ledger lock, releases that lock before native I/O, then clears metadata and wakes fenced admissions. Holding the ledger lock during native release can deadlock streaming callbacks. Shutdown persists live resident histories. Resident switch events report mode=resident and zero save/transfer/restore durations.
