**Qwen3.8-27B-GGUF is the production model for agents and Coin.** The user treats it as the minimum competent work model. Smaller 4B/8B models are not production substitutes. The former Qwen3.5-4B quick-reply model was removed; Lemonade health confirms only Qwen3.8-27B loaded before performance experiments.

- Production shape: `ctx_size` 131,072 with `--parallel 1`. Two lanes require 262,144 total to preserve each agent's allowance.
- Arguments: `--batch-size 512 --ubatch-size 128 --poll 0 --prio -1 --spec-type draft-mtp --cache-ram 0`, plus the snapshot directory. No `--reasoning-budget`.
- The configured 39 GB admission estimate remains conservative; its origin is a roughly 38.5 GB two-lane observation during the September 2026 scheduler rebuild, not a separately measured current one-lane footprint.
- Historical calibration: one MTP request delivered 20–25 visible tokens/s; two concurrent requests about 13 tokens/s aggregate. Prefill near 170 tokens/s meant a 20k-token reread took about two minutes. Current controlled comparisons belong to the benchmark procedure.
- It supports tool calling and uses hybrid recurrent/attention state. Reuse requires a saved state ending at a prefix of the next prompt.

**Weight provenance.** The checkpoint is `unsloth/Qwen3.8-27B-GGUF:Qwen3.8-27B-UD-Q4_K_XL.gguf`, revision `4ca720788d1e01f1bff70c033e0d0028fd02e502`. Public Hugging Face HEAD metadata reports 17,559,178,144 bytes and SHA-256 `3f227079003add2511437e5b1e94812e363385225bf6a9b47b0054a72bc8b01e`. This substantiates the inherited 17.5 GB file estimate, not loaded memory. The Lemonade-owned GGUF is unreadable to this user; the independent copy in `~/.cache/cointos-speed/models` passed that SHA-256. Its metadata is `general.architecture: qwen35`, with 65 blocks.

**Backend candidates.** Lemonade identifies the available gfx1151 GPU and XDNA2 NPU. Vulkan is b10723. ROCm metadata advertises b10711, but the actual trial used installed b10707 (`62acc89c2`) after GitHub availability prevented an update. vLLM 0.20.1/ROCm 7.12.0 lives under `/var/cache/lemonade/bin/vllm/rocm`. Its GGUF loader lacks family aliases, `dt_bias` mapping and correct unsuffixed names. Alias-only still leaves 48 unmapped biases. CPU/meta evidence (`/tmp/cointos-vllm-map-evidence.json`, `/tmp/cointos-vllm-map-fixed-evidence.json`) shows an isolated name fix maps all 851 text parameters in the actual file, leaving 15 MTP tensors. Names alone are unsafe: b10723 Qwen conversion folds `-exp(A_log)`, adds one to non-linear-attention norms, squeezes convolution kernels and reorders grouped V heads to tiled order. Native Qwen35 multiplies by stored `ssm_a`; vLLM expects `A_log` and exponentiates it. Actual `blk.0.ssm_a` has 48 negative values (-0.337585 to -0.003839); raw loading changes the decay coefficient. Its GGUF iterator copies values without reversing these transforms. Validate inverse values/layouts and GPU kernels before a load or benchmark. Installed files remain unchanged; no GPU/checkpoint load was attempted. The FLM catalogue lacks Qwen3.8-27B; its smaller Qwen and Qwen3.6-MoE models do not establish an equivalent work model. `how/to/benchmark/cointos/model/backends.md` owns measurements and comparison limits. Vulkan remains production; no alternative has earned adoption.

**Load-time contract.** Lanes and total context allocate at load. Check health's effective `launch_command`, not saved recipes or advertised versions. CointOS supplies complete arguments with `merge_args: false`, `save_options: false` and pins the model; `backend_llama.models()` verifies effective context/flags before declaring it up. Backend URLs/ports can change on reload and are refreshed from health.
