CointOS combines `roles/_base.md`, one role file and one bounded assignment, followed by the run's daemon-owned budget notice. Everything before the assignment is identical for every run of a role so the backend's shared-prefix cache holds; task-specific text starts only inside the assignment, after its project/location line. That second line is an identity line built from the task record (`Task: <id>, a <kind> task. Your role: <role>.`), so an agent never infers its role from queue-kind mappings or CointOS code; its `cointos` commands act as that task with that role's permissions. Every role follows the bounded-stage rules in `what/is/the/shape/of/cointos/work.md`. Every agent role ends its run with exactly one completion receipt, which the daemon validates against the role's artifacts (`what/is/the/agent/completion/model.md`); final text, finish markers and process exit never complete a task. A role is fixed by its task kind (`cointos/schema.py`); a `command` queue item runs as a `breakdown` task with the manager role. Every role learns CointOS's commands from the runtime tree's `what/is/cointos.md`; a missing operation is reported (`--blocked` or `cointos attention`), never found by reading or working around CointOS itself.

- **Coin** is the Telegram control service. It reports and controls the daemon, manages projects, holds and revises queue items for the user, requests the canonical steward and launches explicitly scoped operators. It does not invent maintenance work.
- **Managers** perform one bounded decomposition or recomposition stage, keep the project plan's remaining frontier honest, and propose children through `cointos queue`. To change their project's already-queued work, even work that has started, they `cointos hold` it and then `cointos revise` it; they never queue duplicates. Failed worker items automatically reach one manager pass, without magic report wording; managers may revise a false brief or replace oversized work while preserving unfinished work. They land their planning changes and finish with `cointos finish --complete|--blocked`; queued children continue independently.
- **The steward** is one low-reasoning system-wide roaming assignment. It inspects runtime state, configured projects and accessible trees, follows the strongest evidence, and stops after one useful result rather than exhaustively auditing everything. Knowledge-tree gardening is normal steward work: it may directly repair stale current truth, non-green leaves it can verify and dishonest plans. Outside knowledge trees it is read-only. When product work or managerial judgment is needed, it may submit exactly one attributed manager command with `cointos queue ... --kind command`; it cannot propose implementation kinds. It may instead perform one bounded registry action when enrollment itself is the concern. If the user must decide or act, it raises a daemon alert delivered by Coin rather than leaving the request in a terminal. Its receipt carries its finding; a clean result is valid.
- **Test auditors** are medium-reasoning system-wide retrospective reviewers. After recent accepted product work, one samples a landing, compares tests with the owning specification, runs bounded suites, and checks whether plausible wrong implementations could still pass. A concrete semantic gap becomes at most one manager command in the owning project; it never edits product code, tests, plans or project knowledge itself. Its receipt carries its finding; a clean audit is valid.
- **Operators** carry one user-requested ad-hoc assignment with explicit standard, control or network abilities. A system operator's receipt states its result without changing product repositories; a project operator must leave clean merged work before a complete receipt.
- **Workers** implement one skeleton, test-contract, implementation or integration item on an isolated branch. They preserve protected tests, commit a single unambiguous `.work-report.md`, and submit that exact commit for review with a receipt matching the report's status. A revised item restarts them on its new brief with their branch intact; they keep only the earlier work it still needs. Tree/plan maintenance is left to the integrator.
- **Integrators** review one worker against current main, contracts and neighboring boundaries. They accept or return it, maintain the owning project tree and land through the daemon's exact-candidate gate. The verified landing, incorporation or return is their receipt; `finish --blocked` fails the item and automatically routes its assignment and receipt evidence to one bounded manager pass. An unresolved or exhausted manager escalates to the user without another automatic pass for the same failure. They may expose at most one same-project managerial follow-up.
- **Gardeners** provide free periodic maintenance across the CointOS source tree and every registered project's knowledge tree, verifying a small selected batch of leaves. **Tree auditors** (task kind `tree-audit`) inspect one structural concern across a representative sample. Both are bounded, mutually excluded per tree and finish with merged knowledge changes and a receipt stating any unresolved result.

The global default is low reasoning. `config/cointos.json` `reasoning` may name a default for test-contract creation/review and for any role by its name; test-contract workers, test-contract reviewers and managers default medium. A task's effort is pinned when it is created, so a changed default reaches only tasks created after the daemon loads it, and explicit daemon-owned task overrides still win. A new integration uses its worker's construction stage to select the review default, without inheriting the worker's explicit effort or budget overrides; integrations reviewing other stages use their role/default effort. Per-reply reasoning limits and total run budgets are separate. Ordinary interruption retains sessions; bounded exhaustion can start an artifact-preserving fresh run. Role class and GPU scheduling priority remain distinct.
