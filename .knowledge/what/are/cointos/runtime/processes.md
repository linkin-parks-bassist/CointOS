- **cointosd:** one Python daemon and the only ledger writer. It hosts the OpenAI-compatible gateway, control/dashboard API, scheduler, lane workers, spawner, lifecycle/recovery, model reconciliation, memory guard, journal and self-check. Separate installed RAM/disk cache-cleanup threads inventory and delete outside the shared state lock, with retired bytes charged until release.
- **Agent unit:** transient cointos-agent-<id>.service, private version-bound OpenCode server/client, worktree, run/task identity and memory cap. New V2 units use an authenticated server and either the native CLI or Python event client for synthetic recovery; surviving V1 units retain their transport. These are control/session processes, not additional inference engines. New construction servers inherit kernel-enforced checkout write confinement. Declared read/external-directory rules and, for insulated/observer launches, kernel read allowlists reject peer/editor metadata while retaining assigned source and permitted tool/knowledge/instruction paths. Assignments name the active checkout first and use accepted refs for main. check_work returns checkout identity. Launch owns exact allowlists and failure policy; adopted servers retain captured permissions.
- **Independent repair:** `boot.py` converts fatal Python daemon exceptions to exit 2; native OnFailure starts `repair.py` through `cointos-repair.service`. Remote Codex bypasses the unavailable local gateway. One native/flock owner retains incident/thread evidence; installation shares that lease. Incomplete execution resumes; checked handback requires current health and daemon-produced restoration evidence, permitting subsequent authorised progress. Native retries share configured `service_restart_seconds` without a start cap.
- **Coin:** owns intake/replies using the shared `work_model` default. An optional `coin.model` is an explicit requirement for a separate configured engine. Direct work, work-update explanations and requested-work completion updates have Coin priority; ordinary wakes have background priority. Its kt actor grant follows it across projects; the Telegram procedure owns scope/transport.
- **Lemonade/llama-server:** machine-level model service outside CointOS. `backend_llama.py` owns its literal API. The installed adapters share conversation preparation and Qwen output parsing through backend_chat.
- **Gufo control:** a private Unix-socket process around the pinned dense-Qwen DFlash2 runner, launched in an independent systemd user scope so compatible daemon replacement preserves it. backend_native dispatches per model; Gufo remains a retained alternative; current production uses Vulkan llama/MTP for Coin/workers with the original steer, while performance experiments are paused (steering/benchmark owners); what/is/the/gufo/backend/candidate/for/cointos.md owns qualification.
