- **cointosd:** one Python daemon and the only ledger writer. It hosts the OpenAI-compatible gateway, control/dashboard API, scheduler, lane workers, spawner, lifecycle/recovery, model reconciliation, memory guard, journal and self-check. Separate installed RAM/disk cache-cleanup threads inventory and delete outside the shared state lock, with retired bytes charged until release.
- **Agent unit:** transient cointos-agent-<id>.service, private OpenCode server/client, worktree, run/task identity and memory cap. New construction servers inherit kernel-enforced checkout write confinement. Read/external-directory tool rules reject canonical editor product files, retaining knowledge/Git/instruction paths; kernel reads remain unrestricted. Assignments name the active checkout first and use accepted refs for main. check_work returns checkout identity. Launch owns exact allowlists and failure policy; adopted servers retain captured permissions.
- **Independent repair:** `boot.py` converts fatal Python daemon exceptions to exit 2; native OnFailure starts `repair.py` through `cointos-repair.service`. Remote Codex bypasses the unavailable local gateway. One native/flock owner retains incident/thread evidence; installation shares that lease. Incomplete execution resumes; checked handback requires current health and daemon-produced restoration evidence, permitting subsequent authorised progress. Native retries share configured `service_restart_seconds` without a start cap.
- **Coin:** owns intake/replies using `coin.model`; agents use `work_model`. Direct work, work-update explanations and requested-work completion updates have Coin priority; ordinary wakes have background priority. Its kt actor grant follows it across projects; the Telegram procedure owns scope/transport.
- **Lemonade/llama-server:** machine-level model service outside CointOS. `backend_llama.py` owns its literal API. The installed adapters share conversation preparation and Qwen output parsing through backend_chat.
- **Gufo control:** a private Unix-socket process around the pinned dense-Qwen DFlash2 runner, launched in an independent systemd user scope so compatible daemon replacement preserves it. backend_gufo serves production construction Qwen through per-model backend_native dispatch; the installed Coin and construction settings share the Gufo work model; what/is/the/gufo/backend/candidate/for/cointos.md owns qualification.
