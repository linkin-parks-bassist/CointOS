CointOS is a personal framework for local models and agents on the user's workstation. Coin provides Telegram access and delegates requested machine tasks to system Operators. The scheduler, gateway, memory guard, durable conversation, reminders and explicitly requested schedules remain online.

The software-factory role is suspended by user instruction. `factory_enabled: false` prevents project construction/integration, discovery Stewards, test audits, gardening and their recovery/supervision chains from being admitted. Existing project enrollments are disabled; queues, tasks, sessions, files and accepted work are preserved. Idle GPU capacity is allowed to stay idle. `how/to/disable/the/cointos/factory.md` owns the switch and restoration procedure.

Requested Operators may work within their assigned authority, including filesystem and machine tasks. Automatic supervision and recovery agents are disabled, including around Operators. Additional roles require explicit Coin/user/tool or timer/reminder dispatch; idle/milestone/failure observation alone creates no agents. Scheduling remains preemptive, with Coin responsiveness taking precedence and dynamic memory controls preserving the desktop. This mode changes neither tool permissions nor authority boundaries and does not certify native model competence.

The optional factory still retains managers, workers, independent tests/review, integration and receipts for later explicit re-enablement. Its unfinished acceptance work is suspended, not completed. Developers preserve live inhabitants and user work under how/to/keep/cointos/simple.md. Only the daemon writes runtime authority; knowledge trees own maintained answers.

what/is/the/spec.md owns requirements; what/is/the/plan.md owns remaining work. Source checks and installed acceptance remain distinct.
