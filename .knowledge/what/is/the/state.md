**Two design fixes from that run.**
- *Delivery:* settlement read an item's status from the task branch first, so a worker that set `Status: done` after `cointos merge` left main saying queued while the ledger said done (levenshtein; roman-numerals earlier). Main is now the one truth for done (`blocked` may still come from the branch); the worker role commits the status with the work before landing. Levenshtein's stranded commits were fast-forwarded onto main by hand. `add-matrix`, the first worker on the new instructions, settled `item status done on main` with nothing stranded.
- *Slices:* the end of a returning thought's read of its tool result restarted the turn's slice clock, so each quick tool call granted a fresh slice. Only a turn's opening read now starts its slice. Deployed 04:13; live confirmation over a longer run is pending.

**Design lessons.** Cold reads must finish before equal-class rotation; backend requests must end at bounded steps; snapshot memory counts against Lemonade's cgroup allowance. Checkpoints and suspended snapshots have distinct lifetimes, and eligible snapshots can spill to disk rather than accumulate without bound. A clock that a condition resets (here, "read done") must say which occurrence of the condition it means.
