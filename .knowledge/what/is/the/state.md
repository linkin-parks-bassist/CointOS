**Incidents that night and their design fixes (all deployed and unit-tested).**
- *Delivery:* settlement read an item's status from the task branch first, so a worker that set `Status: done` after `cointos merge` left main saying queued while the ledger said done (levenshtein; roman-numerals earlier). Main is now the one truth for done (`blocked` may still come from the branch), and the worker role commits the status with the work before landing. Levenshtein's stranded commits were fast-forwarded by hand. Every later item settled `done on main`.
- *Slices:* the end of a returning thought's read of its tool result restarted the turn's slice clock, so each tool call granted a fresh slice. Only a turn's opening read now starts it. Afterwards, a lane trace showed an agent whose turn ran past its slice through a tool call yielding as soon as its read finished.
- *Dropped lane state:* at 04:05 and 05:35, llama-server re-read a whole 25k context inside a 96-token step (150 s at about 160 tokens/s) right after a switch, without logging why; `no agent starves` then failed for 2–3 minutes. The daemon's token accounting was verified against every snapshot file (exact match), so the server had dropped the restored state. Steps now stream prompt progress and abandon at once, before reading, if the server kept less than the lane held (`Lost`); a restored snapshot that did not survive is forgotten. Deployed about 05:58; no occurrence has been observed since.
- *Runaway tool:* at 05:51, an agent's deliberately bug-exposing RLE test (from a brief that allowed digits in RLE text) tried to allocate 1.7 TB. Memory and swap climbed until systemd-oomd killed Lemonade. The models came back in about 25 s by Lemonade's restart plus the daemon's model check. Agent units now run with `MemoryMax=agent_limit_gb` (8) and no swap; the live units were capped at runtime first.
- *Silence after a long thought:* that outage ended a 40-minute thought, and silence was measured from the agent's last OpenCode event, so the agent was ended at once as silent for 2433 s (run charged). A thought's end now counts as activity.
- *OOM kill stopped the whole agent:* with the cap, systemd's default `OOMPolicy=stop` ended the agent's unit when its test was killed, so the RLE task was rerun into the same kill (runs 2 to 4 in minutes). Units now use `OOMPolicy=continue`: only the largest process (the tool) dies and the agent sees exit 137; verified with a test unit. While moving the RLE run onto the new policy, `cointos stop AGENT` was used by mistake. It abandons the task by design (no requeue), so the task failed. It was re-queued on sandbox main with a corrected brief: digits cannot round-trip in that RLE format, and `encode` should reject them.

**Interrupted replies (open gap, now characterised).** Tested against OpenCode 1.18.32 with a fake server (`how/to/launch/opencode/for/a/cointos/agent.md`). OpenCode retries only an HTTP error returned *before* streaming. A stream cut after content (which is what a daemon restart does) is kept as a partial finished step and the conversation goes on from it. An `error` chunk inside the stream, which the gateway sends whenever a thought fails (a model killed, a backend failure), ends the whole `opencode run`. So a restart during generation, and any failed thought, can end an agent's run. At 06:07 a restart did exactly this: the partial message's next render failed with HTTP 400 at llama-server's template endpoint (cause not established), and the manager was ended as silent (charged; it resumed in the same session). Design options for David: return the HTTP status only once the first output exists (errors before output then become retryable 503s, but a waiting client gets no headers, which matters for David's own sessions if their client has timeouts); and render a partial trailing assistant message so the model continues it. Until then, avoid restarting the daemon while agents generate.

**Server-side prompt cache (finding, unchanged).** llama-server keeps its own RAM prompt cache ("making room for prompt cache entry", entries about 4.3 GB, 72 evictions overnight). **Design lessons.** Cold reads must finish before equal-class rotation; backend requests must end at bounded steps, and the backend must verify rather than assume that the server kept a lane's state; snapshot memory counts against Lemonade's cgroup allowance. Checkpoints and suspended snapshots have distinct lifetimes, and eligible snapshots can spill to disk rather than accumulate without bound. A clock that a condition resets (here, "read done") must say which occurrence of the condition it means. Anything an agent runs needs a hard memory bound of its own, or the machine's OOM handling chooses the model server.
