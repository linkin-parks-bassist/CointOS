Expected mistakes remain local; requested-work completion is a separate notification category. Conversational Coin replies are model-generated and visible through Telegram within fifteen seconds, for direct requests and qualifying updates. No canned conversational replies or metadata headers. Do not add engagement questions; consequential decisions require a clear contextual question, otherwise take the recommended option. Each model round receives current time/date/timezone; evidence retains source timestamps and unknown dates. Distinguish history from current decisions. Use configurable batched history: twenty messages drop by seven to thirteen; preserve the archive and reusable prefixes. All incoming text/captions and accepted outgoing messages, including notices and partial sends, enter that history. Preserve reply-to references across rollover and correlate answers with the current owning work before scoped action and verified completion. Retain unfinished user instructions independently until verified completion or cancellation. Use bot-identity tree grants. Inspect/queue work, manage projects/services and request scouts/Operators. Explain behavior, files, owner, cause and next action plainly; personal decisions require context, actors, actions, consequences, trade-offs and a recommendation for a technical user unfamiliar with this code.

3. Share available model lanes among more agents than lanes and keep them productively occupied when work exists.
4. Urgent/queued work, commands and discovery progress without the user. Resolve test placement, ordering and implementation sequencing within engineering recovery, preserving every requirement and later witness.
