Separate backend phase speed, active-call throughput and wall-time utilisation. Bind comparisons to the same model, lane, PID, task/session, sampling, template, context and vector settings. Cross-backend unmatched samples do not isolate a steer's cost.

Dashboard Generation is output tokens divided by decode time: llama exposes decode_seconds from timings.predicted_ms; Gufo supplies native generation_seconds. Reading uses processed prompt tokens/time, including continuation preparation when exposed. Llama returns prompt_n/prompt_ms for explicit prefill and the hidden prefill inside think; cached tokens are excluded. Reading is therefore a tail metric: with prefix caching only the uncached extension is processed, so low values can reflect tiny-chunk overhead rather than cold-prefill cost, and snapshot I/O is excluded. Every bounded generation step is preceded by a short preparation prefill, so Reading moves during writing: about two processed prompt tokens per generated token, with larger tails on rejected drafts or cache loss. Without native reading timing, use the bounded reading-call measurement as a proxy, labelled in the tooltip.

Active total beneath Generation divides output by active backend-call duration, including preparation/API work; initial reads contribute time with zero output. It excludes lane waiting, snapshot I/O and tool execution, so it is not whole-session wall throughput. Phase filters are independent one-pole EMAs, alpha=1-exp(-phase_seconds/10); inactive phases hold and restart resets them. MTP divides matched smoothed accepted/proposed rates. The llama adapter forwards draft_n/draft_n_accepted; no proposals means undefined, not zero acceptance.

Agent-card rate is the last completed decode step: llama predicted_n*1000/predicted_ms, Gufo output/native generation_seconds including pending-token consumption. Sixteen output tokens are required; a displayed sample can persist during reading/waiting. Llama's legacy generation_seconds still measures completion-call wall time for existing budget accounting; it is not the new decode_seconds. Do not use that counter as pure native decode speed or silently change pinned spending semantics.

For a wall-time study, use actual capture timestamps and matching counter deltas, including HTTP endpoint uncertainty. Subtracting backend prompt/generation timers from elapsed time leaves unaccounted time, not proof of its cause. Trace cache, transport, scheduler and adapter costs before attribution. Preserve both the native rate and actual delivered throughput; changing a label is not a speedup.

gpu_seconds includes preparation; add active gpu_since at observation endpoints. Its difference from charged generation_seconds includes preparation, cache work, adapter work and boundary skew. thought.read is a high-water mark, not newly processed input. Switch events separate save/transfer/restore: transfer includes admission/readiness and disk-to-RAM work; restore is native. Totals include every compatible attempted candidate, including failures. restore_tier names the last attempt. Rejected bring_back performs no native restore; failed restores retain time/broken_snapshot before trying shorter prefixes. Overall switch time ends with ledger update; later journal publication and following prefill are separate.

Gufo speculation totals retain matched token/time denominators; include correction/frontier tokens when explaining tokens/round. Footer hashing does not isolate serializer cost. Source/installed telemetry was verified with 73 focused checks, a captured-native timing contract and live API phase/acceptance samples. Isolate probes from user work, preserve sessions/spend/authority, group interruptions and verify useful resumed generation. Transport/restoration alone does not prove assistant quality or useful throughput.
