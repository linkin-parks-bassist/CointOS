The Machine panel's Default model chooser uses GET /api/models to combine on-disk GGUFs from model_directories and configured recipe directories with configured downloaded Lemonade models queried through its API and explicit Halogen recipes. Lemonade entries use lemonade:MODEL identifiers and retain their configured launch recipe; the service resolves protected caches and complete split checkpoints. dashboard.model_discovery_seconds owns its refresh interval (fifteen seconds). Each poll rescans directories, but models.metadata parses a file's GGUF header once per identity (device, inode, size, mtime): parsing skips tokenizer arrays in GIL-held Python for about 0.7 s per 17 GB file, and repeated parses from open dashboards starved the daemon's API threads past client timeouts. Filename-matched draft/vision companions and partial downloads are excluded; unavailable entries appear under collapsed Unavailable models details. The chooser lists usable entries with readable variant/quantization labels; standard Qwen 3.8 27B comes first. Tooltips retain original names. New qwen35 files use a Gufo recipe, checked SHA256 and no speculative draft until explicitly qualified. Memory admission derives weight size and overhead from the configured recipe.

POST /api/default-model accepts one exact discovered path identifier, including lemonade:MODEL and halogen:MODEL. models.py owns checking → draining → loading → ready, with restoring/failed on errors. Shared-default replacement rejects a recipe without private-session state support before persisting or unloading anything. It closes new chat admission while current replies finish, persists desired identity before native mutation, unloads the old default unless explicitly required, checks headroom and verifies native launch before active routing changes. It shares the replacement lease against installation. Failed loads attempt native cleanup and restoration of the previous configuration/engine; errors remain visible. Restart retires unused configured engines and reconciles the persisted selection. Upgrades retain the selected default and discovered recipes; source definitions override matching recipes.

Ordinary requests resolve to work_model. OpenCode config, command and session spec use cointos/default; old concrete names retained by surviving clients also follow it. Sessions, tasks, spend and artifacts remain. Optional coin.model expresses a separate explicit requirement; ordinary Coin omits it. required_model requests can only name already-required engines. New spawning and silent-agent enforcement defer during replacement; loading time is not an agent stall.
