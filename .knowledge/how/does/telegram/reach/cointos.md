Coin is the independent Telegram service in cointos/coin.py. Credentials stay outside source in the configured environment file. The daemon owns task lifecycle and inbox delivery; Coin owns conversational intake, replies and dispatch coordination.

One request flow distinguishes five facts:

1. **Received.** coin_input.py atomically/fsyncs allowed text/captions, media descriptors and cursor in private state/coin/inputs/intake.json before advancing Telegram polling. Damaged authority refuses unchanged; legacy cursor migration runs only without new authority. Transport dates and reply-to text/IDs survive intake and history rollover; unknown old dates remain unknown. Removed users cannot execute.
2. **Replied.** Newly admitted user input requires an accepted nonempty model reply before tools or silent completion. Later admitted input reopens that obligation. Empty/failed sends do not count. The guard checks execution order while stable tool schemas retain prefix reuse. Receipt language must not claim unperformed file changes; wording and fifteen-second responsiveness remain model-dependent.
3. **Dispatched.** run_agent starts scoped direct work; queue_item sends product goals through planning. Both carry selected original text, IDs, timestamps and reply references in received order alongside the model's scoped brief. Multiple current inputs require input_ids binding the assignment's sources; unknown IDs refuse and unrelated originals are excluded. Briefs remain scoped. coin_followups retains user/chat-bound owners and exposes cointos-dispatched-work outside rolling history. update_work forwards continuations to that existing owner's active-task inbox without kill/revise/restart. Repeated values in distinct messages remain meaningful; one input ID identifies one message on replay.
4. **Consumed.** Inbox acceptance establishes handoff, not that an agent understood or executed it. The daemon owns active-task validation and delivery. A settled-owner refusal requires inspecting the result before new scoped work. Coin does not duplicate task lifecycle or restart an owner merely to add input.
5. **Verified.** The service observes declared handoff/replacement closure before result verification. Managers/Operators own product supervision; Coin reads exact returned evidence paths. Intermediate planning does not wake Coin; completion turns cannot rearm wakes. coin_reports records user/chat/canonical-location/stable-milestone outcomes outside rolling history. report_result requires successful current-turn fs_read/run_command call IDs; repeats send nothing. Completion wakes and done-task watches suppress ordinary send/closing prose until fresh user input arrives. Plans, routine repairs and unrelated green tests do not establish deliverables. Evidence relevance, outcome naming and moved-file judgment remain model-dependent; reporting does not authorise recreating deliverables.

Plain text takes precedence; initial conversational admission is half history_messages, with genuinely newer arrivals admitted up to history_messages. Captionless attachments save/route without model turns or history slots. standing attachment_route/attachment_route_stop rules handle incoming photos without quotas; collisions preserve existing files and successful receipts prevent resurrecting organised files. Focused attachment/history owners retain replay and filesystem contracts.
