Coin saves allowed Telegram photos, documents, animations, video/audio, voice notes, video notes and stickers without interpreting them. Photos select the largest supplied size; duplicate document/animation references are deduplicated. Intake persists descriptors, captions, album identity and cursor atomically before acknowledgement. Unknown types are ignored.

Captionless attachments are filesystem work. A permanent attachment thread downloads them independently of the model worker, settles successful input IDs, and leaves failures retryable with failed.json diagnostics. They consume no conversation-history slots or model turns. Without a standing route they remain in the inbox. Text and captions still reach Coin; captioned files are saved before their metadata enters context. Permanent download refusals on captionless inputs remain local/status-visible rather than triggering a model reply; captioned refusals remain model-visible. Saving sends no canned Telegram receipt.

attachment_route(destination, operation=copy|move) stores one durable photo destination per transport user under state/coin/routing. Copy is the default. The rule has no expected-total quota and survives restart until changed or stopped. It applies to captionless photos received since the current instruction, including files saved while the model established the rule. Current captioned attachments can join during registration; unrelated captions require model handling. attachment_route_stop stops future routing, preserving delivered files. A quiet queue does not end a rule. attachment_status describes received/saved/routed receipts and failures, not how many files the user intended to send.

coin_attachments.py owns atomic inbox saves under state/coin/attachments/USER/UPDATE/INDEX/files/, Telegram-size checking and initial SHA-256 receipts. coin_routing.py owns origin metadata, routing and delivery receipts. Delivery uses deterministic photo_UPDATE[_INDEX] names and ordinary filesystem completion, without repeated hashing. Existing destinations are preserved; only collision resolution hashes files. One failure does not stop other inputs. Replay reuses saved/delivered receipts without downloading or resurrecting later-organised files. Delivery is recorded before removing a moved inbox original; interruption can leave an extra original. Removal of an allowed user prevents further processing.

Telegram's hosted Bot API controls downloadable size; Coin adds no cap. Image understanding needs a separately validated backend/media path and is unavailable here.

Source evidence: coin.py, coin_attachments.py, coin_routing.py; tests.test_coin_routing exercises 294 photos with zero model/send calls and no extra verification hashes, restart, registration races, user isolation, cancellation, captions and partial failure.
