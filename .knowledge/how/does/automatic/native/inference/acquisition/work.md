ecosystem/managed_inference.py request(model, messages, max_tokens, ..., root=..., control=...) is the native loaded-model acquisition entry point. It computes actual routing claims, derives Coin priority from the trusted control caller or user priority from a bound active operator session, and waits/refetches benign stale or occupied capacity. Callers do not supply leases or credentials. Timeout bounds inference execution, not resource waiting. Automatic unloaded-model residency is wired and live-qualified for a prior normal-mode native request. In pressure or emergency mode, the installed native loop waits before route/realization so it cannot override the resource guard's model profile. It persists the halted reason only when that state changes and rechecks after one second rather than rewriting a durable record ten times per second. Waiting for readiness still does not by itself prove a loader ran.

Each logical request retains model/messages and caller PID plus kernel start ticks in state/inference-runs/native-<id>.json. Each attempt acquires a workload-control worker, starts a gated child, registers its PID/start ticks, reserves a worker-bound sequence, writes one credential into an anonymous memfd and releases the gate. Raw credentials are absent from durable records and command arguments. Retry clears stale child/worker/inference fields; reconciliation uses the authoritative capacity lease bound to the CURRENT worker rather than an old attempt's inference_lease_id. Input survives suspension. Caller-death reconciliation never replays model/tool work merely because a process ended.

The first durable starting record includes spawn_intent=False. The marker becomes True before attempting gated_child_launch; child identity is recorded after registration. False proves this attempt did not initiate a spawn. True with no registered identity, or a legacy missing marker, does not prove never_spawned: retain reconciliation_required with next_check=verify_worker_birth. A child prevented from executing by its gate is still a genuinely spawned process. Unknown birth requires a journal/ownership interface before automatic cleanup can be established.

Launch failure and descriptor ownership: before a launch attempt, native setup owns and can close its memfd. Tagged executor spawned=False failure proves nonbirth and consumes the descriptor. Tagged spawned=True permits reaped_spawn only when actual cleanup state is reaped AND process_group_alive=False; unknown cleanup is retained. Missing launch_failure after an attempt proves neither nonbirth nor FD consumption. Do not close the old numeric FD blindly: tagged cleanup already closed it, and descriptor reuse could target another owner. os.pipe failure outside the executor try can instead leave it open. That untagged ownership ambiguity is an explicit executor-interface blocker. Ambiguous failures remain scannable reconciliation_required rather than terminal failed. The real post-Popen KeyboardInterrupt regression verifies preservation of the original interruption, quiescent actual worker and zero backend requests after verified cleanup.

reconcile_dead_callers(root, clock=...) scans eligible nonterminal native records, checks dict shape/id-to-filename consistency and original caller incarnation, and reports live/recovered/retained/cancelled/ignored counts plus pending reasons. Kernel observations distinguish ok/absent/unreadable: absent or differing start ticks proves the original caller gone; unreadable or malformed evidence is retained. A reused live PID is not signalled. Live owners are left unchanged. An unissued attempt closes only with actual process/nonbirth evidence; issued attempts retain physical occupancy until verified backend termination. An already-quiescent issued worker still requires finalizing its durable record, so replay of reconciliation does not strand it. This is an explicit API; periodic/startup wiring and live restart recovery remain unqualified.

Workload-control release is separate from end observation. For process=None, proven never_spawned or actual reaped_spawn plus a release outcome can quiesce the lease. Registered processes instead require matching top-level PID/start ticks and explicit process-group/backend/inference absence fields; reaped_spawn on a registered lease classifies it dead_unreconciled. Worker leases are entries in state/workload-control.json, not files under state/worker-leases. See how/is/an/unregistered/worker/released.md for that classifier contract.

Native cancellation order: the request monitor observes sequence preemption_requested, sets its local preempted flag, calls proxy.cancel and leaves the process loop. proxy.cancel closes registered local streams, durably marks the credential closing and returns cancellation_requested/in-flight count; this is cancellation intent, not backend-end evidence. _finish requires a reaped gated process with group absence, then completed_run_termination before revoking an issued credential/releasing occupancy. Unissued sequences are withdrawn. Only after verified closure does a preempted request record suspended and retry; unknown end stays retained.
