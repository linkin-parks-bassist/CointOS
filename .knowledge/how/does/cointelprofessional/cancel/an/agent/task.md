Cointelprofessional exposes `cancel_task` with an optional exact `agent_name`. The tool is idempotent through the control-turn action ledger and calls `cli.request_task_cancellation` using the authenticated caller source, so it cannot select another caller's task. With no name it selects the most recently updated active caller task.

The durable CLI transition takes the executor lock, then the task-enqueue lock, then the verification-finalize lock. This matches claim/recovery ordering and serializes cancellation of an awaiting-verification target against verifier finalization. Queued, ready, and awaiting-verification work becomes terminal `cancelled` immediately. Running work retains its state and gains `cancellation_requested_at` plus a cancellation reason. The executor checks that durable marker before capacity and priority preemption on every preemptible loop, and cached-job persistence adopts it so a concurrent request cannot be erased. `_durably_claim_job` terminalizes a ready job with a cancellation marker before launching another runner. If the executor dies while a cancelled job is still `claimed` and no runner admission began, dead-owner recovery now terminalizes it directly instead of briefly returning it to `ready`.

After the runner process and both leases are safely closed, `_complete_requested_cancellation` reads the authoritative record and terminalizes any durable cancellation before finite-budget or priority continuation logic. The immediate post-close, late-preemption, and runner-exit checks now use this same transition rather than duplicating cancellation fields. Cancellation therefore wins even when `_run_preemptibly` reports both `preempted` and `budget_checkpoint` in the same outcome. It records `state: cancelled`, `logical_run_state: terminal`, `runner_close_state: cancelled`, removes pending continuation/reconciliation metadata, preserves any retained OpenCode session only as evidence, and never queues that session for resumption.

Both jobs are now terminally cancelled.
