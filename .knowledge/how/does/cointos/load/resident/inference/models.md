The live model-inventory entry point is `ecosystem.models.snapshot(root=None, clock=None)`; the module has no `inventory()` function. `snapshot` returns the document consumed by `ids`, `admission`, routing, and `realize`.

`scripts/load-resident-models` is the boot-time residency owner. It configures two resident LLM positions and pins the control model with its configured context pool. `resource_control.load_emergency_model` separately performs qualified emergency allocation, calls `/v1/load`, and verifies live health. `unload_dynamic_models` preserves the emergency model and active operator-owned models. These are boot and emergency operations, not the general model acquisition path.

The general no-eviction producer now exists in `ecosystem/resource_control.py`. `model_residency_status(health, model_name)` consumes one observed health document and classifies an exact unique model record as `live`, `not_live`, `not_loaded`, or `unavailable`; duplicate records are unavailable. `model_residency_availability(health, maximum_loaded_models)` validates a positive non-boolean maximum, counts records whose `loaded` field is exactly true, and returns `free`, `full`, or `unavailable` with occupied and free counts. `model_load_payload(...)` validates the requested model, total backend context, parallel count, and pin flag, then builds the current Lemonade llama.cpp load document.

`load_model_if_residency_free(...)` composes those helpers. It observes health once; returns `already_loaded` for a live exact match; waits for unavailable health, a present non-live record, or full residency; calls `/v1/load` only when a position is observed free; then observes health again and reports `loaded` only when the requested model is live. Backend failure and failed post-load verification return explicit wait results. It does not evict, unpin, persist scheduling state, or infer priority. Direct injected checks cover health failure, already-loaded, present-non-live, full, backend-error, successful-load/reverification, and unverified-post-load branches; `python3 -m py_compile ecosystem/resource_control.py` passes.

The closed idle-residency victim path now exists in `ecosystem/resource_control.py`. `select_idle_residency_victim(health, protected_model_names)` is pure (no I/O, no policy lookup). The protected collection must be a list, tuple, set, or frozenset of nonempty strings, otherwise `ValueError`; it is normalized to a set. The selector reuses `_health_models` once; invalid health returns `{state: unavailable, error: ...}`, and duplicate `model_name` records return `{state: unavailable, error: duplicate model records}`. A record is eligible only when `model_is_live(record)` is true, `record.get("is_busy")` is exactly false, and its name is not protected; a `pinned` flag alone does not protect. Selection is the lexicographically smallest eligible name, returned as `{state: selected, model_name, record}`; with no eligible record it returns `{state: wait, reason: no_idle_residency_victim}`.

`protected_residency_model_names(control_model, *, root=None)` derives the idle-reclamation protected set with no health, network, or policy lookup and no state mutation. `control_model` must be `None` or a nonempty string, otherwise `ValueError`; when present it seeds the set. `root` defaults to `cli.ROOT` in the existing `root or cli.ROOT` style. On `unloaded` it calls `load_model_if_residency_free` exactly once more with identical arguments and returns the second result plus `reclamation` as a new dict, without mutating the subordinate result. There is no loop, sleep, priority inference, ownership lookup, extra unload, or service control.
