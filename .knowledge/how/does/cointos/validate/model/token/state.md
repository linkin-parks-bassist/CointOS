Continuation readiness is backend-specific. llama extends its prepared prefix with a pending real token, establishing the hybrid checkpoint for the next buffered step; its equal-length restored-state checks would discard cache. Gufo retains the full published vector with next-token state and continues directly from equality. can_continue exposes these contracts to lane placement, decode chunks and snapshot selection; token identity alone is not readiness. Gufo exact continuation reattaches its token index through PrepareContinuation while preserving learned draft policy. A published pending token advances physical and logical history exactly once; consuming it or restoring a snapshot is not a new request. Real native checks include direct prefix extension and reasoning closure, not only decode speed or fork replay. Prompt preparation streams progress so loss can refuse before unbounded rereading. Generation returns bounded token vectors without per-step text parsing, checking complete counts and cached lengths. The backend owns the known retained prefix; speculative draft state beyond returned tokens stays cold. UTF-8 fragments remain valid token history and assemble before outward streaming. Missing terminal events, backend errors, incomplete vectors and nonterminal zero-token steps cannot become known lane state: the thought fails and its lane becomes cold.

A native EOS is not by itself a usable assistant answer. After final parsing and the existing construction pre-stop check, a non-length reply with neither nonblank content nor tool calls is incomplete, even if it generated reasoning. The gateway returns incomplete_response as JSON HTTP 502 or an explicit SSE server_error, never an ordinary successful stop. Token-limit replies retain length semantics for continuation; real tool calls and answers remain valid. This neither synthesizes task completion nor changes role budgets/retry limits. Native OpenCode 1.18.35 retried a reasoning-only SSE error within the same process and obtained a second-request answer from a local stub. Managed-model benefit remains unproved.

Every thought belongs to one gateway request. The handler cancels on every exit, including pre-header errors, and polls peer EOF while waiting for JSON/streaming replies. Waiting thoughts disappear immediately; in-flight steps finish before release. Caller timeouts cannot leave detached high-priority work. Released runs lose gateway keys; later requests with them refuse (410) before admission. New requests during shutdown receive retryable refusal.
