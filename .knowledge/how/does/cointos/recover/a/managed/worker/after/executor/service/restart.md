`recover_abandoned_jobs()` examines managed runner records only after their exact executor owner is no longer alive. A dead `claimed` job has not begun runner admission: recovery now terminalizes a durable cancellation request directly, otherwise returning the claim to `ready`, instead of momentarily scheduling cancelled work. An in-flight runner still needs verified process-group absence and `close_runner_round()` evidence for backend termination, proxy revocation, inference release, and worker quiescence. An uncertain process or backend observation remains `reconciliation_required`; recovery does not invent release evidence.

A completed `_run_preemptibly` round now writes `runner_round_outcome` with its runner generation before physical close begins. A new generation clears that evidence. If the executor dies after close, recovery checks the exact generation, saved child return code, process-group absence, and close state. It then replays the same priority order: durable cancellation first, budget checkpoint second, preemption third, then ordinary success/acceptance or failed-run notification. A failed record left before physical close must finish that close before replay. A malformed or contradictory new outcome is held in `reconciliation_required` for review, not guessed into completion. The logical-finalized generation prevents repeat processing of a terminal failed result.

Legacy `run_finished` records without a saved round outcome are deliberately left untouched, because an exit code alone cannot reconstruct a lost budget/preemption decision. The prior restart path for records without new evidence still uses the retained OpenCode session when safe. Nine temporary-root `tests/test_executor_post_close_recovery.py` checks cover successful completion, artifact rejection, budget, preemption, cancellation, legacy evidence, inconsistency, malformed checkpoints, and pre-close failure. Current standard `tests/` discovery passes 837 tests, and the separate process-integration discovery passes 33. This is source/test qualification, not a current live restart exercise. A prior bounded live exercise did verify exact-session recovery on Qwen3.8 with fresh leases.

New terminal records now persist their result-notification recipient snapshot with terminal state. The outbox creation remains a separate write, but periodic idempotent reconciliation repairs a missing result message without resending an existing delivered or ambiguous one (`how/does/cointos/avoid/duplicate/result/notifications.md`). Legacy post-close records lacking the round-outcome envelope still need conservative operator review rather than automatic completion. Requalify live restart, cancellation, and notification behavior after safe recovery from the held emergency; do not disturb professional ingestion.
