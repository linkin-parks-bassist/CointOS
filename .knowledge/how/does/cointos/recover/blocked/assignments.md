Recovery belongs to a canonical assignment/version. frontier.py derives its obstruction, corrective handoffs and one First Responder, a distinct role (`roles/first-responder.md`, task kind `first-response`). Its sole duty is to work out why a run went wrong and dispatch the right agent with the right brief; it does not do the work. Its file edit tools are denied, its budget is small (`recovery.role_budgets`, 30,000 tokens and 1,800 seconds) and calling agents does not charge it. `cointos_dispatch` lets it start any role except another First Responder, and Coin is not a dispatchable role for anyone. Failed construction/planning, infrastructure admission holds and taskless invalid dependencies use this route. Controllers run serially per project; unrelated work remains eligible.

Operator is separate: the user's direct or uncategorisable work. An Operator from before this role can hold an assignment's controller slot; the user replaces it with `dispatch` role `first-responder` and the failed task.

A Supervisor (`roles/supervisor.md`, task kind `supervise`) stays with a run until it ends, by the user's requirement. `recovery.supervise` requests one when a run's generation passes each multiple of `recovery.supervise_every_seconds` (1,800) if none is live, for every role but itself and never for a run past its budget. Any agent can also dispatch one with `task`. It starts past `spawner.max_agents` while memory allows, its own scheduling class preempts background runs on the GPU below Coin and the user, and memory pressure still stops it. It reads `cointos transcript` and leaves files alone; its budget is 1,800 seconds and 40,000 tokens. Its two main tools, by the user's decision, are steering with `cointos_send` and `cointos_revise`, which clears the run's context and replaces its assignment with the Supervisor's own brief while branch and files stay, so progress is kept. It revises instead of letting a run compact. `lifecycle.evidence` refuses its complete receipt while the run is going; a blocked receipt summons no First Responder. When the run ends, an unstarted Supervisor is cancelled and a running one is told to dispatch any follow-up and is cancelled after `recovery.supervise_wrap_up_seconds` (120). Its role lists what implementers may not do: probes, scope expansion, test edits, unrequested design or knowledge work, endless verifying.

`split` (Coin's `split_work`, `cointos split`) stops an implementer or Operator judged too big, keeps its branch and files, and replaces the assignment with a manager item whose brief names those places and demands much more aggressive decomposition. Other roles refuse it. A First Responder that exhausts its budget splits an implementer origin once; otherwise the blockage escalates as ownerless.

Unstarted garden recovery waits for its first completed health observation, then while selected canonical answers are deferred. A completed read failure does not suppress recovery; started controllers retain context/allowance. Availability restores eligibility. The managed-tree owner holds asynchronous observation and stale-result checks.

An assignment or its current controller can propose continuation, including after exhaustion. The complete dependency closure must remain runnable: holds, unknown/cyclic/terminally blocked edges and backedges to the origin disqualify it. Obsolete-version children cannot hide current blockage. Runnable children neither complete parents/controllers nor invent receipts or refill budgets. Ownerless, unheld blockage queues evidence for Coin after coin.blocked_notify_seconds; active recovery and continuations suppress escalation. A dependent of blocked work only waits: it raises no alert or red check, and the blocked item answers for itself. A substantive user notification requires the model. Routine recoverable mistakes stay local; only unfixable problems or concrete workflow deficiencies merit unsolicited updates. Queueing is not delivery.

Launch and CLI/MCP inspection share current queue authority, binding tests and typed pending corrections. Historical briefs cannot override them. Ordinary packets claiming replacement in prose never change acceptance. Implementation/integration requires actual accepted test-contract edges; empty or obsolete receipts cannot authorize landing.

Any running agent holds queue authority, resumes after infrastructure repair and, unless it is the implementer bound by them, requests independent correction of invalid accepted tests. A correction handed to one test-contract successor through `cointos_replace` stays a correction, so its acceptance still rebinds consumers. Old acceptance binds until review. Pending corrections prevent consumer admission, completion, landing and incorporation; final gates recheck corrections arriving during validation. Implementation artifacts and explicit holds survive activation. Preserve known counterexamples with the original obligation, exact source/probe refs and command/result through handoff. A passing wrong implementation cannot be cleared by narrowing its coverage description.

Complete recovery requires an origin change with reachable continuation, cleared admission hold, checked maintenance or runnable independent correction. cointos_replace validates existing-work closure and clean landed artifacts before repointing dependents and completing atomically. Unknown/cyclic/held/blocked replacements and actively reviewed dependents refuse before mutation. correct-tests similarly checks handback and completes recovery atomically; manager/ad-hoc correction requests remain nonterminal.

Pending canonical drafts are an authority boundary. Preserve them regardless of author identity. Without authorized reconciliation, return blocked.

Changed authorized assignments can restart exhausted workers on preserved artifacts; identical revisions cannot refill budgets. Revisions preserve explicit holds and revoke obsolete controllers. Withdrawal removes mutation authority but permits checked closure. Construction, Operators and First Responders default to zero fresh allowances. Unchanged product-validation refusals remain blockage; execution failures count separately.

Prelaunch and submission composition failures enter recovery directly, with structured evidence in frontier.inspect. `spawner.retry_compositions` restarts such an item by itself once its tests merge, when it is blocked and unheld with no live controller or pending correction, trying each exact main and packet set once per daemon run outside LOCK. A pending correction delays the restart until it settles.

Product acceptance remains separate from recovery handback.
