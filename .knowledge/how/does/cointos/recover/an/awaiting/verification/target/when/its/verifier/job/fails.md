A failed linked verifier is finalized against its waiting target after a closed runner, not replaced by a new verifier. Ordinary `execute_next` calls `verification.finalize` after persisting its failed state. Dead-owner post-close replay takes the same path only after validating generation-bound observed outcome and physical-close evidence. A failed verifier always rejects the target: if it left a valid `accepted: true` artifact, `verification.finalize` records an effective `accepted: false` verdict and an explicit runner-failure summary while leaving the original artifact on disk. A successful `run_finished` or `completed` verifier may accept only a schema-valid accepted verdict. This separates verifier-process success from the artifact's self-report.

If execution stops after the verifier's logical-finalization marker is persisted but before target finalization, `watchdog.reconcile_verifications` now detects a linked failed verifier whose generation, close state, reaped process group, and logical marker match. It calls `verification.finalize` and queues the target notification. `finalize` serializes target updates with `verification-finalize.lock`, changes only an `awaiting_verification` target, and returns an already terminal target linked to the same verifier without rewriting it. A concurrent different terminal transition is not overwritten. Periodic result-notification reconciliation handles a crash after target publication. This does not create a second verifier or infer close from a mere `failed` state.

A verifier that fails before a runner generation or lacks matching physical-close evidence still needs separate conservative handling; this repair does not turn incomplete evidence into a terminal target.
