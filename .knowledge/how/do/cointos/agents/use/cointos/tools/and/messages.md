`cointos/mcp.py` is a stdio MCP server that OpenCode starts for each agent run (`python3 -P -m cointos.mcp`, with `PYTHONPATH` at the installed runtime and the run's `COINTOS_TASK_ID`/`COINTOS_AGENT` in its environment; `opencode.settings` adds it as the `cointos` server). OpenCode exposes its tools as `cointos_<name>`.

Each tool builds an argument vector for the matching `cli` command and runs it in-process, so arguments never pass through a shell and the CLI and tools share one implementation. Required arguments are checked before running. The server keeps the real stdout for protocol messages and points file descriptor 1 at stderr, so subprocess output cannot corrupt the stream. Before the tools, about half of agents' shell `cointos queue` calls failed on quoting of long briefs.

A run sees only its role's tools: everyone gets `finish`, `task`, `jobs`, `status`, `peers`, `send` and `inbox`; integrators add `review`, `land`, `return`, `incorporate` and `queue`; managers add `queue`, `hold`, `revise`, `cancel`, `replace`, `supersede`, `budget` and `merge`; stewards and test auditors add `queue` and `attention`; gardeners, tree auditors and operators add `merge`. The daemon still enforces every permission. `roles/_base.md` tells agents to call `cointos_<command>` wherever instructions name a `cointos <command>`; the shell CLI remains for the user. Runs launched before an installation keep their launch-time configuration, so only new runs get the tools.

**Peers.** `peers` lists every other live run: task id, role, state, its brief's `Summary:` line, current activity (`doing`), and `git diff --stat` of its worktree against its base commit. `roles/_base.md` asks agents to check peers before changing shared files or interfaces and to send an overlapping run a short note; nobody waits for a reply.

**Messages.** `send` puts a short message in an active task's inbox (ledger `messages`, last 200 kept), or alerts the user through Coin for `to: user`. A sender must be the task's current run, or the user's CLI (`cointos message TO "TEXT"`, `cointos inbox`). The gateway (`gateway.with_messages`) delivers each unread message on the recipient's next model request as a user turn `<message from="TASK">TEXT</message>` at the end of the conversation and marks it read; agents spend runs in bash/read/edit, whose results cannot carry a notice. OpenCode does not store that turn, so it is invisible in the TUI and the gateway re-inserts it at the same anchored position on later requests, keeping the cached prefix identical. `inbox` returns messages not yet delivered. A user typing in an agent's attached OpenCode viewer instead posts a real, persisted user message to its session.

Evidence: `tests/test_mcp.py` covers catalogues, verbatim briefs, protocol calls, messaging, peers, gateway placement and anchoring, and config wiring. Live: a manager used `cointos_task` and `cointos_replace` without shell calls; a demo operator messaged the live Pigen worker, which saw the gateway-delivered message on its next step, replied with one sentence about its task and continued; the operator finished with the reply as its receipt.
