`cointos/mcp.py` is a stdio MCP server that OpenCode starts for each agent run (`python3 -P -m cointos.mcp`, with `PYTHONPATH` at the installed runtime and the run's `COINTOS_TASK_ID`/`COINTOS_AGENT` in its environment; `opencode.settings` adds it as the `cointos` server). OpenCode exposes its tools as `cointos_<name>`.

Each tool builds an argument vector for the matching `cli` command and runs it in-process, so arguments never pass through a shell and the CLI and tools share one implementation. Required arguments are checked before running. The server keeps the real stdout for protocol messages and points file descriptor 1 at stderr, so subprocess output cannot corrupt the stream. Before the tools, about half of agents' shell `cointos queue` calls failed on quoting of long briefs.

A run sees only its role's tools: everyone gets `finish`, `task`, `jobs`, `status`, `peers`, `send` and `inbox`; integrators add `review`, `land`, `return`, `incorporate` and `queue`; managers add `queue`, `hold`, `revise`, `cancel`, `replace`, `supersede`, `budget` and `merge`; stewards and test auditors add `queue` and `attention`; gardeners, tree auditors and operators add `merge`. The daemon still enforces every permission. `roles/_base.md` tells agents to call `cointos_<command>` wherever instructions name a `cointos <command>`; the shell CLI remains for the user. Runs launched before an installation keep their launch-time configuration, so only new runs get the tools.

**Peers and messages.** `peers` lists every other live run: task id, role, state, its brief's `Summary:` line, the agent's current activity (`doing`), and `git diff --stat` of its worktree against its base commit, committed or not. `roles/_base.md` asks agents to check peers before changing files or interfaces another task might share, and to send an overlapping run a short note; messages are informational, nobody waits for a reply. The daemon's `send` action puts a short message in an active task's inbox (ledger `messages`, last 200 kept), or alerts the user through Coin for `to: user`. `inbox` returns the asker's unread messages and marks them read. A sender must be the task's current run, or the user's CLI (`cointos message TO "TEXT"`, `cointos inbox`) outside any run. Every tool result except `inbox` ends with an unread-message notice; that is how a busy agent learns of messages, since nothing is injected into a running session. Work still moves only through the queue and receipts. Peers matter only when two or more runs are live at once.

Evidence: `tests/test_mcp.py` (role catalogues, a brief with quotes, newlines and shell syntax queued verbatim, protocol list/call, messaging both ways, sender and recipient checks, peers with summary, activity and changed files, config wiring). `opencode mcp list` with a generated agent config reports `cointos` connected, and a real `peers` call against the installed daemon listed the live worker with its activity and diff. Live use: the first manager launched with the tools (`manager-3a5a68`, decomposing a Pigen item) called `cointos_task` three times and `cointos_replace` once, all successful, with no shell `cointos` calls, and finished with a checked receipt. Agent-to-agent peers and messaging have not yet been observed live.
