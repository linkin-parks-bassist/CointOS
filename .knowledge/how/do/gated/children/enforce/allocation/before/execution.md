ecosystem/executor.py gated_child_launch starts a process in a new session blocked on a private gate pipe, validates PID/start ticks/PGID, and optionally passes one config memfd. The child cannot exec until gated_child_release writes a one-byte authorization after revalidating identity. Release closes parent gate/config descriptors; the child retains its inherited config fd. gated_child_wait returns a cached reaped outcome including process_group_alive. gated_child_cleanup closes gates, signals only the matching owned process group, bounds TERM/KILL waits, reaps and retains reconciliation_required when absence cannot be proved. Config fd None provides the same gate without credential storage. These primitives support a short-lived native inference child so its allocation can be closed without terminating the long-lived Telegram gateway.

The internal gated_child_launch setup boundary now catches BaseException, not just Exception. Exact failure ABI: when its cleanup completes, gated_child_launch re-raises the original BaseException with error.launch_failure. Before Popen birth the record is {spawned:False}. After birth it is {spawned:True,pid,start_ticks,pgid,cleanup}; start_ticks may be None if identity validation was interrupted. cleanup is the gated_child_cleanup outcome. A reaped outcome has state=reaped, returncode, pid, start_ticks, pgid and process_group_alive=False. Reaped leader with group absence unverified remains state=reconciliation_required; a wait-timeout outcome may contain only state,returncode=None,pid,start_ticks and therefore supplies no group-absence proof. Consumers must map start_ticks to process_start_ticks for workload-control observations and use reaped_spawn only for an unregistered lease. A registered lease instead requires matching top-level identity/absence observations. If cleanup itself raises, that secondary error can escape before metadata assignment; missing launch_failure does not prove spawned=False. This schema is checked directly from gated_child_launch, _reaped_outcome and gated_child_cleanup, not inferred from a successful task exit.

Config-FD ownership at failure: an invalid config_fd argument raises before ownership/metadata. For a valid supplied fd, child_argv or child_env validation errors tag spawned=False and close that fd. os.pipe currently runs before the protected launch try; pipe-creation failure leaves the supplied fd open and no launch_failure. Once the pipe exists, the returned gate owns the supplied config_fd (there is no internal dup), passes it via pass_fds and closes the parent copy through release/cleanup. Tagged launch failures consume/close the supplied fd, including reaped and reconciliation-required cleanup outcomes; callers must not blindly close its old numeric fd again, since another thread can reuse the number. Untagged errors require phase/ownership evidence rather than assuming either closed or caller-owned; cleanup itself may have raised before metadata assignment. config_fd=None records -1 and transfers no credential fd, while gate descriptors still have normal ownership. Direct source: gated_child_launch argument validation, pipe/try boundary, config_record_fd, and gated_child_cleanup descriptor closure.
