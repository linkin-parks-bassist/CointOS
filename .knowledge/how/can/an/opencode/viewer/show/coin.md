Coin is a Python service. `cointos coin professional|amateur` selects an identity; standalone omission asks or uses COINTEL. Automatic slots never ask: the reported worker PID selects its profile service. Slot identity changes detach the old display. The watcher reads state/coin-<identity>/turns.jsonl. Live text requires matching owner identity; untagged/other-profile previews are suppressed. Profile journal viewers are installed; gateway owner tagging is staged pending a quiet daemon reload. Viewer titles and model labels use the selected profile's name. cli.coin_log/show create a private derived display from the selected journal, backfill the latest60 entries and follow the current live record. The bounded journal owns history; display storage/server disappear when the window closes. Rich coin_view remains the startup-failure fallback. Ordinary Cointel archives and turn journals remain independent of viewer cleanup; global steer-capture can also retain their full requests. Personal disables diagnostics, so it produces no journal to replay. OpenCode incognito settings alone cannot remove those copies.

With opencode_v2 enabled, coin_mirror_v2.py runs a password-protected private OpenCode2.3.0 server and native --server/--session terminal. Server XDG/config/model inventory are isolated; the terminal retains the user's UI preferences. Installed OpenCode v2.3.0 accepts OPENCODE_DB=:memory: in debug paths db. The separate cointos-private launcher qualifies memory-only user sessions with log suppression and crash cleanup; how/to/run/a/user/opencode/session/alongside/cointos.md owns it. Ordinary viewers still use disposable on-disk stores. Existing windows keep imported code until reopened. V1 survivors retain coin_mirror.py's original prompt_async/part-PATCH mirror; those APIs are not used on V2.

V2 has no supported live message-part PATCH/upsert API. Its replay provider instead emits ordinary native reasoning/text/tool events from journal entries. Its sole executable tool, coin_observation, fetches an already recorded result by native call ID. Displayed inputs retain the original tool name/arguments, and metadata supplies the original title. It never invokes Coin controls, CointOS MCP or the model gateway. The plugin removes other tools/models and rejects non-replay execution. Typed text receives the Telegram/view-only explanation rather than reaching Coin intake.

Live reasoning remains reasoning_content and live words remain content. Append-only updates stream normally; overlapping capped suffixes extend accumulated text. Native streams cannot retract already emitted text. If the authoritative finished journal differs from the preview, the recorded reasoning/reply is shown explicitly rather than silently dropping it. Ordinary matching final entries do not duplicate the preview. A stale live record of the completed step stays suppressed.

User entries enter the native inbox in queue mode; journal tools close a provider step with a replay call, and subsequent journal reasoning/text continue after its recorded result. Idle/next-user boundaries finish the display stream. Backfill can lag while native events are replayed; no latency or resident-memory claim from V1 is transferred to V2. A viewer slot ends when Coin becomes idle, while cointos coin remains open between turns.

tests.test_opencode2_native covers native replay of reasoning, words, a recorded tool/result, following reply, refusal of typed control and cleanup using no real model. Its terminal case separately verifies attachment to the owned private session. The V1 viewer's older native/PTY tests remain scoped to that implementation. These are assisted display/transport checks, not Coin judgment or Telegram-delivery acceptance.
