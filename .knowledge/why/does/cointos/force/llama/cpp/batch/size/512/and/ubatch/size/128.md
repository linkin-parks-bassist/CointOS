CointOS forces llama.cpp `--batch-size 512 --ubatch-size 128` in dynamic, emergency and boot-time model load paths. These override current llama.cpp defaults of 2048/512. The pair entered `config/resource-policy.json` in commit `4d4045e60f9bec1dca43885f1dc1c6839b16befd` on 2026-09-04 without recorded rationale.

A controlled Strix Halo benchmark on 2026-09-16 now supplies a reason to retain the pair for Qwen3.8-27B under Lemonade 11.9.0 / llama.cpp build b10723-010be9683. Each run used the same freshly loaded pinned Qwen3.8 model, 131072 context, one parallel sequence, MTP draft speculation, an identical 46,700-token uncached synthetic prompt, 128 maximum output tokens, and no concurrent request. Effective live commands were inspected.

Results:

- forced 512/128 first run: 188.05 prompt tokens/s, 20.32 decode tokens/s, 252.08 seconds total;
- upstream-default 2048/512 run: 131.67 prompt tokens/s, 19.41 decode tokens/s, 357.70 seconds total;
- forced 512/128 reverse-order confirmation: 185.96 prompt tokens/s, 20.08 decode tokens/s, 254.04 seconds total.

The reverse-order result confirms that 512/128 improves this large-prompt workload by roughly 42% in prompt throughput relative to upstream defaults; the difference is not explained by simple run order. Retain 512/128 for the currently qualified Qwen3.8 load configuration. This measurement does not prove the pair is globally optimal or appropriate for every model.

Benchmark artifacts are `/tmp/cointos-batch-benchmark/{baseline.json,defaults.json,baseline-confirm.json}` for the current host session. During the experiment Qwen3.5 remained pinned and untouched. Qwen3.8 was restored pinned at 131072 with 512/128. Its saved and effective options omit the stale `--reasoning-budget 2048`.

Next check: after higher-priority bring-up work, compare nearby candidates such as 1024/256 using randomized or alternating order, and qualify settings per model/backend version rather than treating this pair as universal.
